Privacy

Debagr has no analytics, advertising, crash SDK, customer account or Debagr cloud. Nothing is sent to the publisher. It processes device names and identifiers, app paths, deployment results, developer-tools status and private connection metadata on your own Macs.

Cable sharing in current source builds. An SSH-owned helper forwards device services from one fixed cable endpoint. Control uses existing SSH credentials and trusted host keys. Data listeners bind to the cable host’s Tailscale address and allow only the selected Builder’s Tailscale source address. Apple’s existing pairing authenticates the device session. Debagr stores no passwords. The separate USB/IP setup uses peer discovery and role linking while its screen is open or a role is saved. Raw USB traffic travels between the two Macs over your private network.

Stored data. Private profiles and receipts persist under ~/.config/debagr/. UI preferences remain in com.debagr.app. USB/IP role keys and session logs are stored under ~/Library/Application Support/Debagr/.

Diagnostics. Reports go to the clipboard and leave the Mac only when you share them. They omit traffic payloads and Bonjour TXT values but can contain device names, private addresses and ports. Review before sharing.

Support

  1. Confirm Xcode and devicectl are installed on the build server.
  2. Pair over USB, trust that Mac, and enable Developer Mode.
  3. Keep the device unlocked for the first install.
  4. Confirm the signed device .app exists on the build server.
  5. Test the Debagr command locally before invoking it through SSH.
  6. Choose Copy Diagnostics, review the result, and share it only through private reporting, below.

Contact

Report problems in GitHub Issues with the exact macOS, Xcode, and iOS versions. Never post device identifiers, hostnames, VPN addresses, pairing material, or diagnostics in a public issue.

Send security vulnerabilities, privacy requests, and requested diagnostics through GitHub private vulnerability reporting. Support is best effort during the technical preview.

Uninstall

Stop any cable CLI session with Ctrl-C. Turn off Launch at Login, quit Debagr and move the app to Trash. Back up profiles before removing ~/.config/debagr/ or clearing com.debagr.app preferences. Older setup data under ~/Library/Application Support/Debagr/ is not used by current source builds; review it before deleting. Removing Debagr does not revoke Apple pairing, uninstall deployed apps, or remove VPNs or third-party tools. These instructions apply to current source builds; published release notes document older versions.
