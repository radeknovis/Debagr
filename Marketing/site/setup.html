Debagr

Your first deployment

This guide covers Debagr 0.3.0, a technical preview for Apple-silicon Macs. Managed remote deployment needs macOS 26 or later on the Mac. The preview is free for personal and internal evaluation and may not be redistributed.

Already paired, or Builder nearby

The Builder is the Mac that builds your app, owns the Apple pairing with your device and runs the deployment. Everyday wireless deployment needs only this one Mac.

  1. On the Builder, install current Xcode and Debagr: brew install --cask radeknovis/debagr/debagr.
  2. If the device already trusts the Builder, enable Developer Mode and test a local signed build. For a new pairing, connect directly by USB and approve Trust, or see USB/IP setup if the Builder is elsewhere.
  3. Connect the Builder and the device to your private VPN. Keep the device nearby on the same Wi-Fi for this step.
  4. Click the Debagr icon in the menu bar and choose Open Debagr. With no saved device, the Connections window opens on Use existing pairing. Select the paired device and choose Continue. Select your VPN provider, the device's VPN address and its nearby service, then choose Continue. Confirm that the selections refer to the same physical device and choose Save & check connection.
  5. Leave Debagr running in the logged-in Mac session. Enable Launch at Login if you want it to start with the Mac. Move the device to another Wi-Fi network and keep it unlocked with the VPN connected. Cellular-only operation is unsupported.

Deploy

  1. For a natural-language request, tell your agent: Use Debagr on build-server to install and launch /path/to/MyApp.app on my iPhone. Replace the SSH alias and signed app path with yours.
  2. Download the matching Claude Code or Codex plugin ZIP from Releases. Extract it and follow its included README installation instructions.
  3. Run /Applications/Debagr.app/Contents/MacOS/Debagr --devices --json on the Builder. Select the intended Apple identifier, then run --status --device <UDID> --timeout 30 --json.
  4. Build a signed device .app on that Mac, or copy the complete signed artifact there. Run readiness again after building, then --deploy-app /absolute/path/App.app --device <UDID> --launch --json. Allow 180 seconds. Report success only when installed and launched are both true.

For a remote agent, use your existing SSH access as the same Mac user. The plugin does not set up SSH, signing or Apple trust.

On failure, run --diagnose --device <UDID> --timeout 30 --json and follow its recovery instruction. An installation timeout has an unknown outcome; run --installed-apps --device <UDID> --json before retrying. If only the launch failed, run --launch-app <bundleID> --device <UDID> --json instead of reinstalling.

Pair with a new Builder over USB/IP

This experimental option in the source candidate is for an iPhone or iPad that needs to trust a remote build Mac. Keep both Macs on a private VPN. The nearby Mac needs the patched Longcable exporter. The Builder needs usbip-macos and virtual USB controller access. The experimental importer currently requires SIP off on the Builder. Both Macs require administrator approval.

  1. Plug the unlocked device into the nearby Mac. Open Pair via USB/IP on both Macs and link them as Client and Builder. Compare and confirm the code if Debagr shows one.
  2. Export the selected device from the nearby Mac (Client). Import it on the Mac that builds and deploys (Builder). Approve Trust on the device if Apple asks.
  3. Check that Xcode on the Builder can deploy to the device. After that succeeds, stop the import, then the export. If the Builder is elsewhere, export the nearby wireless service profile on the Client and import it on the Builder. Finish wireless setup and check deployment with the cable unplugged.

In the cabled iPad test, a Mac mini installed a signed app, read back build 6 and launched it using pymobiledevice3. Xcode saw only a restorable device. First-time Trust, native Debagr deployment and an unplugged VPN handoff still need verification.

USB via Mac

Experimental CLI in current source builds. The USB via Mac guide describes forwarding RemotePairing and tunnel services from a phone plugged into another Mac. Run debagr --cable help and follow the bundled cable sharing guide.

Both Macs need Debagr, Tailscale and trusted SSH access. Supply a saved device profile, the cable-side scoped IPv6 endpoint and RemotePairing port. The phone must already be paired with the Builder. Keep USB connected; the phone needs no Wi-Fi on this route. No extra USB tool, administrator password or SIP change is required.

One iPhone passed authenticated readiness and signed-app installation with Wi-Fi off. Launch, debugger, automatic discovery and reconnect are not accepted by that test.

Verified and not yet verified

Verified on hardware: one remote iPhone installation and OS-confirmed launch over Tailscale on 10 November 2026 with a 0.3.0 candidate build. A confirmed launch is not a test of the app's interface.

Not yet verified for 0.3.0: first launch on a clean Mac, first launch offline, independent wireless iPad deployment, recovery after restart, sleep and wake, a network change, revoked trust or denied Local Network permission, VPN providers other than Tailscale, macOS 13 to 15, the Homebrew upgrade from 0.2.0 to 0.3.0, and cable bridge launch, debugger and recovery.
