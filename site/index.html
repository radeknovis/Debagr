How Debagr Works

Debagr never transfers Apple trust records, never signs apps, and opens no deployment network listener. It uses your Mac's native devicectl and a supervised DNS-SD proxy over your private VPN.

Install via DMG or Homebrew Cask

Homebrew Cask (Easy Updates)

Installs both /Applications/Debagr.app and the debagr CLI on your PATH.

brew tap radeknovis/debagr
brew install --cask radeknovis/debagr/debagr

Verified vs. Experimental vs. Out of Scope

Capability Status Notes & Honest Requirements
Wireless Deployment ("Use Existing Pairing") Primary Requires one already-paired physical iPhone/iPad on Wi-Fi + private VPN (Tailscale/Headscale auto-discovery; ZeroTier/NetBird/WireGuard manual private IP).
Structured CLI & Local Stdio MCP Primary Readiness, install, verification, launch, and redacted doctor diagnostics over local terminal or SSH. Recoverable exit codes for locked devices and partial install success.
USB via Mac (Cable Service Bridge) Experimental Terminal-driven bridge for an already-paired device plugged via USB into a second Mac (even with Wi-Fi off). Forwards port 62078 over 127.0.0.1 + SSH + VPN. No root or SIP changes.
Pair via USB/IP (Temporary Raw USB) Experimental Guided two-Mac coordination with Curve25519 + 6-digit SAS verification supervising separately installed USB/IP tools only after explicit user approval, then hands off to wireless.
Trust Transfer, App Building/Signing, Simulators, Cellular-Only, Cloud Out of Scope Debagr intentionally keeps Apple trust, Xcode, and signing on the Builder Mac. No companion iOS app, no user accounts, no telemetry, and no cloud servers.
