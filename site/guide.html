Setup & Operations Guide

Configure Debagr in four steps.

Set up once while your already-paired iPhone or iPad is near your Builder Mac, then deploy from anywhere over SSH or MCP.

1. Primary Workflow — Wireless Setup ("Use Existing Pairing")

  1. Pair normally once: Connect your iPhone or iPad to your Builder Mac with a cable in Xcode/Finder, accept Trust This Computer, and enable Developer Mode on the phone.
  2. Run Debagr Wireless Setup: Open Debagr.app from your menu bar while the phone is awake on the same Wi-Fi network.
  3. Select your Private VPN:

    Click Discover VPN Peers. Debagr queries the local tailscale status --json CLI, filters for your private CGNAT/ULA IP, and tracks peer IP changes automatically.

    Select your VPN provider and enter your phone's private VPN IPv4/IPv6 address (RFC 1918, 100.64.0.0/10, or IPv6 ULA fc00::/7). Public IPs are rejected for safety.

  4. Confirm hardware & save: Select the discovered _apple-mobdev2._tcp local identity, confirm it matches your physical device, and save. Debagr writes config locally with 0600 permissions.
Automatic Yield & Sleep Recovery: Whenever the device is plugged in via USB or already connected on local Wi-Fi, Debagr steps aside into Native Local Connection standby. Across Mac sleep/wake or Wi-Fi changes, it automatically tears down stale mDNS records and re-probes your VPN.

2. CLI, SSH & Coding-Agent Onboarding

Symlink the embedded binary so terminal scripts and SSH logins can invoke debagr directly:

sudo ln -sf /Applications/Debagr.app/Contents/MacOS/Debagr /usr/local/bin/debagr

Safe agent workflow (locally or over SSH):

ssh dev@builder-mac debagr ready
ssh dev@builder-mac xcodebuild -scheme MyApp -sdk iphoneos -destination 'generic/platform=iOS' build
ssh dev@builder-mac debagr deploy --app /path/to/MyApp.app --terminate-existing

MCP Configuration (debagr mcp)

{
  "mcpServers": {
    "debagr": {
      "command": "debagr",
      "args": ["mcp"]
    }
  }
}

Packaged Claude Code (plugins/claude-code) and Codex (plugins/codex) plugins include this MCP config and the shared debagr-deploy skill.

3. Recoverable Error Codes

Error Code Exit Recommended Recovery
DEVICE_LOCKED 3 Ask the user to unlock the device and run debagr ready, or pass --no-launch to install without launching.
INSTALL_SUCCEEDED_LAUNCH_FAILED 4 App is already installed & verified. Do not rebuild or reinstall; unlock / trust profile on iOS, then run debagr launch --bundle-id <id>.
OPERATION_TIMEOUT_UNCERTAIN 5 Inspect post-timeout state via debagr ready and debagr apps before retrying.

4. Experimental Fallback Routes

Experimental: Both routes below are clearly marked experimental for situations where normal Wi-Fi + VPN deployment is not yet available.

Experimental A: USB via Mac (Cable Service Bridge)

For an already-paired device plugged into a second Mac (even with Wi-Fi off). Forwards usbmuxd port 62078 strictly on 127.0.0.1 through SSH over your private VPN — zero raw USB sharing, zero root, zero SIP changes.

# On the Client Mac where the phone is plugged in:
debagr experimental cable-bridge client --udid <device-udid> --port 22078

# On the Builder Mac:
ssh -N -L 127.0.0.1:22078:127.0.0.1:22078 <user>@<client-vpn-ip>
debagr experimental cable-bridge builder --instance <bonjour-instance> --port 22078

Experimental B: Pair via USB/IP (Temporary Raw USB)

Guided two-Mac helper for initial Apple pairing when an unpaired iPhone/iPad is physically away from the Builder Mac. Uses Curve25519 + 6-digit verification code and requires explicit user confirmation before supervising separately installed third-party usbip tools, then hands off to Wireless Setup.

debagr experimental usbip check
debagr experimental usbip guide
